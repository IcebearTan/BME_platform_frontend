# 反馈工单：现场采集与处理流程

维护日期：2026-11-02。用户端全路由反馈入口、管理端工单处理及配套 Flask 契约。

## 用户侧

- `FeedbackBubble` 仅在 user `App.vue` 挂载一次，Teleport 到 body；按钮固定在右下角，包含登录、注册与窄屏页面，高于业务弹窗和导览。反馈自己的表单/预览层级更高，保证可操作。
- 保留原有绿色发光玻璃胶囊和悬停 `报个Bug` → `(^_^)`、移开还原的趣味交互，宽度弹性由 DewButton 提供。专属配方在 user `styles/feedback.css` 集中维护；扩展功能时不要擅自简化这些既有视觉与交互。可访问名称始终为“报个Bug”。
- 点击时重新采集当前可见视口，后台按需加载打包的 `html2canvas-pro`；不加载外网脚本，不采集整页 DOM 上传。反馈窗口和悬浮球从快照排除。
- 快照可预览、移除，失败/超时仍可提交；同时允许 1 张手动补充图片。两类附件各限 5MiB，支持 PNG/JPEG/WebP/GIF。生成快照本身不向工单 API 上传，点击提交才发送。
- 页面信息包含经过筛选的 URL、标题、视口、滚动位置、主题、版本、浏览器与采集时刻。URL 仅保留已约定的导航参数，不带 hash 或认证票据。密码/验证码输入及 `data-feedback-private` 标记区域在截图副本中隐藏。
- 快照是浏览器对页面的重绘，受跨域资源、canvas、iframe 和浏览器能力限制；无法可靠采集时保留手动图片入口，不阻断反馈。
- 提交仍要求登录；匿名页面可以打开反馈，表单说明登录要求。关闭窗口保留本窗口草稿，重开采集新现场；退出/换号清理账号草稿与图片。提交成功清空。个人中心“我的反馈”展示处理说明、来源与附件。

## 接口增量

`POST /feedback-tickets` 继续接收 multipart `title` / `description` / `category` / `severity?` / `image?`；新增：

| 字段 | 含义 |
| --- | --- |
| `snapshot` | 自动生成的视口图片，与 `image` 分开计数 |
| `page_context` | 定位信息 JSON，服务端再次筛选字段和 URL 参数 |

不新增数据库列：现场信息与快照附件 ID 记在既有 `created` 事件 metadata；文件进入既有附件表/storage。详情增加 `page_context`，附件增加 `kind: snapshot | upload`；历史附件默认为 upload。附件继续走短签/JWT 和资源归属校验，不提供无鉴权直链。

部署配套后端后再发布前端；后端兼容旧表单和历史工单，不需要本轮数据库迁移。旧后端会忽略新增字段，不能用于验收自动快照。

## 管理端

- 队列分为全部、待受理（new/reopened）、处理中（triaged/in_progress）、待用户、已完成；支持类型/优先级/处理人及关键词筛选，URL 保留筛选和分页，详情返回保留位置。
- 问题现场、处理安排、下一步动作和沟通轨迹分别展示；消息与事件按时间交错，公开回复与内部备注明确区分，内部备注不通知用户。
- 新工单先受理；保存处理安排不会再次推进状态或重复发送受理通知。未保存安排先保存后再推进，所有写操作防重复提交。
- 要求用户补充时必填公开说明，说明与 waiting_user 转换同一事务保存；用户回复后自动继续处理。
- 解决时选择方式并填写用户可见说明，之后可关闭或重开。重开清除当前旧解决结果/完成时间，原结果保留在事件轨迹。
- 合法动作优先使用服务端 `allowed_transitions` / `can_triage`。请求带 `expected_status`，后端行锁内检查，状态过期返回 409；前端刷新状态并保留未发送回复。现有 SQL 行锁的并发行为仍须在实际 MySQL 部署环境验证。
- 新增管理接口：`GET /admin/feedback-tickets/stats`、`GET /admin/feedback-tickets/staff`；均要求原 system_management 权限。候选处理人仅有效管理员。
