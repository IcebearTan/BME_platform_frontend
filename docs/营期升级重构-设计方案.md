## 1. 目标与非目标

### 1.1 目标

1. **身份解耦（Phase 1a，先行）**：全局角色收敛两级 + 约 48 处 `user_mode` 门禁清账删列 + `camp_role` 改查营内任职。与营期细节完全正交，可独立部署。
2. **共用营期骨架**：CampCycle 周期归类 + category（learning/project）+ 独立生命周期（主状态+双子流程）+ CampPolicy 配置 + 统一营期中心。
3. **单轮志愿 + 线下协调 + 回填确认**：导生资格名单定向报名；学员入参与者池并在市集页**提交 3 志愿（单轮）**；老师**导出志愿 CSV → 线下与导生协调 → 批量指派回填**（导生可经勾选页自助确认，共用 roster API）；服务端做唯一性/上限/权限校验，沉淀正式归属 + 只追加事件。
4. **项目营闭环**：申报版本→审核→展示→勾选组队（3 上限）→中期/结题节点→材料版本→成果核验→结营档案。
5. **结营档案**：关键事实冻结、普通写全关、档案修正版本化留痕。
6. **课程独立、进度绑营**：移除自主加入学习；课程委托/范围授权后置阶段 5。
7. **留痕**：CampMembershipEvent + CampAuditEvent 只追加，作为未来等级评价系统的数据底座。

### 1.2 非目标（本期不做）

- 两轮在线候选池、抢选、自动匹配引擎、线下表格导入平台（B-004）
- 临床调研型/比赛型营期（R-001）
- 独立资料库/通用文件夹（R-005）；项目任务、经费台账、复杂多评委评分（Q-005）
- 等级评价系统、干事体系、搜索、个人主页、感谢信模板、站内信（Phase 3+）
- `check_record.camp_session_id` 落实写入（已知债不动）

## 2. 总体模型

```
平台身份（两级）：super_admin / user            ← Phase 1a 收敛，§4
CampCycle 营期周期（2026暑等，只归类统计，无状态）
└── CampSession 具体营期（learning | project，独立生命周期+双子流程+CampPolicy）
    ├── CampParticipant 参与者池（营期身份；由 camp_member 演进）
    ├── CampMentorEligibility 导生资格批次（学习营；名单→确认→定向可见）   ← 学习营
    ├── CampUnit 组织单元（mentor_team | project）
    │     ├── mentor_team：导生报名确认后自动建，1 导生 1 组               ← 学习营
    │     └── project + ProjectProfile + ProjectApplicationVersion         ← 项目营
    ├── CampUnitMember 单元成员（单元身份：leader/member；项目 3 上限）
    ├── CampLearningMatch 学习营正式归属（每生一导生，强唯一）              ← 学习营
    ├── CampMembershipEvent / CampAuditEvent（只追加留痕）
    ├── CourseOffering → Course（阶段 5，范围内开课）
    └── CampArchive / CampArchiveRevision（结营冻结+受控修正）
```

三层身份映射（融合同事 §11.4 与两级平台角色，见 §10 裁决①）：

| 层级 | 取值 | 载体 |
|---|---|---|
| 平台身份 | super_admin / user（+admin_tag 审计标签） | `user.role` |
| 营期身份 | organizer / manager / participant 等 | `CampParticipant.role` |
| 单元身份 | mentor_leader / project_leader / project_member | `CampUnitMember.role` |

## 3. 数据模型

约定：无 Alembic，`scripts/migrate/` 幂等脚本（§7）；沿用同事 §14 的实体命名，与现状表的映射如下。

### 3.1 User：全局角色收敛（不变，Phase 1a）

`role ∈ {super_admin, user}`（teacher→super_admin，mentor/student→user）；`+ admin_tag(teacher|developer)` 仅审计；`user_mode` **清账删列**（§4.3）；新增 `PUT /admin/users/<id>/role`（任命管理员唯一入口）。

### 3.2 CampCycle（原方案 term 改名对齐）

`code('2026-summer') UNIQUE / name / sort_order`。无起止日期、无状态、无草稿（R-003、A1）。建营时下拉选择+行内新建。

### 3.3 CampSession：类型与生命周期

| 变更 | 内容 |
|---|---|
| `+ category` | `learning | project`（学习型=培训营；research/competition 枚举预留不实现）。存量全部回填 `learning`；旧 `camp_type` 退役 |
| `+ cycle_id` | FK CampCycle，新建必填 |
| **状态机定稿（H-004，用户 2026-09-02 拍板，取代同事文档基线）** | 五态线性：`draft` 草稿(筹备，仅管理员可见) → `upcoming` 待开放(导生资格导入+导生报名+名片布置；学员见卡片无报名入口) → `selecting` 选择阶段(学员报名入池+市集交志愿+导出/指派/锁定团队) → `running` 进行中(课程/考勤/请假/奖励) → `archived` 已结营(只读+档案)。**无 cancelled**（黄掉的营：draft 直接删，开营后黄的直接结营）。迁移 draft→draft、active→running、archived→archived；迁移走 `POST /transitions`（目标动作制，条件更新+审计）；upcoming→draft 允许撤回，结营不可逆。原 application/formation 子窗口方案作废——窗口即状态 |
| `+ policy` | FK CampPolicy：报名方式、勾选方式、项目参与上限（默认 3）、课程策略等；类型默认值写在代码常量，营期行可覆盖（避免主表膨胀） |
| `ms_*` 字段 | `mentor_selection_enabled/ms_tags/ms_preference_start/ms_preference_deadline` **保留**（名片标签 + 单轮志愿窗口）；`ms_round1_deadline/ms_round2_deadline` 退役（无第二轮） |
| 可见性 | 营期中心列表：running/可报名 preparing 对全员；历史（closed）对参与者；**preparing 的导生入口仅资格名单内可见**（§3.6），营期卡片本身是否对全员展示按营期中心规则（待我处理/即将开始分组），非名单用户不渲染导生入口 |

### 3.4 CampParticipant（camp_member 演进，保留表名避免外键 churn）

营期人员池 + 营期身份。现有 `camp_member` 即此表：`UQ(camp,user)` 保留；`role` 语义升级为营期身份（`participant/mentor/organizer…`，现状 student/mentor 值兼容读取）；`team_mentor_id` 退役路径=由 CampLearningMatch 承接（迁移期双写，读切流后删列）。`source/appointed_by/joined_at` 保留；评价字段预留（A7）不变。

### 3.5 CampJoinRequest（入池申请）

保留现有表与审批流，`apply_role` 语义改为营期身份申请（学员入池）。管理员可直接拉人入池（source='assign'）。**09-02 补④**：+`preferred_tag`（报名时选的意向大组，服务端校验须在本营 ms_tags 内；admin 申请列表与 mine 均带出）；报名入口在营期工作台内（CampJoin，按 category 分发，项目营机制阶段 3 预留）。**09-03**：+`POST /sessions/<sid>/join-request/cancel` 撤回本人 pending 申请（导生报名/学员入营通用，手滑可反悔；撤回后可重提新行，已审批历史不可撤）；前端三处撤回入口（工作台导生报名卡/CampJoin 待审核卡/CampHome 招募页）。

### 3.6 CampMentorEligibility（学习营导生资格，新表 ×2）

```
CampMentorEligibilityBatch: camp_session_id, imported_by, status(preview/confirmed), created_at
CampMentorEligibility:      batch_id, camp_session_id, user_id, confirmed_at, confirmed_by
                            UQ(camp, user)
```

- 导入两步：`import-preview`（dry-run，报告未匹配/重复项，唯一账号标识待冻结——阶段 0 确认项）→ `import-confirm`（幂等，产生定向可见资格）。
- 名单内用户在 preparing 期看到该营期导生入口，**自行报名**（幂等，无二次审核）；报名即入参与者池（role=mentor）+ 自动创建其 `mentor_team` 单元。
- 报名后可布置导生名片（沿用 CampMentorProfile：照片/bio/tags；**capacity 退役**——R-009 无统一容量，管理端只显示人数统计）。formation 开放前不可见学生名单。
- 非名单用户看不到导生入口，手输 URL 后端 403（`CAMP_NOT_VISIBLE`）。
- 存量 mentor 成员回填为「历史已确认资格」。

### 3.7 CampUnit + 项目实体（新表）

```
CampUnit:   camp_session_id, unit_type(mentor_team|project), name, status, visibility, owner_user_id
            UQ(camp, unit_type, name)
ProjectProfile:       unit_id UNIQUE FK, 背景/目标/所需能力/招募说明/计划/公开范围
ProjectApplicationVersion: project 单元 FK, version, submitted_by, leader_user_id, 快照字段, status(draft/pending/review)
```

- mentor_team：导生报名确认时自动创建（1 导生 1 组，name=导生名），无独立管理界面。
- project：负责人申报（版本化，退回重提不覆盖）→ 管理员审核通过时负责人关系生效（Q-006：老师线下指定，平台不遴选；同营期一人最多负责 1 个，无联合负责人）→ 通过后进项目广场（按 visibility 展示公开字段）。
- **大组（软件组/硬件组）不建表**：沿用 `ms_tags` 标签体系（导生名片挂标签，筛选按标签）——A13-1「仅类别标签无管理」的最小实现；若后续需结构化再升 CampUnit kind=direction（见 §10 裁决③）。

### 3.8 CampUnitMember + CampMembershipEvent（单元身份与留痕）

```
CampUnitMember: unit_id, user_id, role(leader|member), status(active|ended), started_at, ended_at
                UQ(unit, user)
CampMembershipEvent: camp_session_id, unit_id, user_id, action(select/deselect/adjust/exit/remove),
                     source(offline_confirmation|admin_adjust), operator_id, before/after, occurred_at   （只追加）
```

- **统一勾选 API**（学习/项目共用）：`GET /camp/units/{unitId}/selection-roster`（候选名单：资格、已选状态、`current_project_count/remaining_project_slots`、当前各单元身份）+ `PUT /camp/units/{unitId}/member-selection`（`expected_version` + `idempotency_key` + operations[]，逐项返回 added/removed/unchanged/conflict/forbidden）。
- 学习营规则：每生一导生——`CampLearningMatch(camp, student_user_id UNIQUE, mentor_user_id, unit_id)`（由 camp_mentor_match 演进），并发勾选锁参与者行，冲突返回现有归属（`LEARNING_ASSIGNMENT_CONFLICT`）。
- 项目营规则：每人同营期计入上限的有效关系 ≤3（CampPolicy.project_limit，默认 3，负责人自己的计入）；事务内锁 `(camp,user)` 参与者行重计数后写入（`PROJECT_MEMBERSHIP_LIMIT_REACHED`）；批量按 user_id 排序加锁防死锁，逐人独立成败。
- 团队锁定（formation locked）后负责人不可普通勾选；变更走管理员调剂（带原因+审计）。锁定后退出/移除记录 ended + 事件，历史提交与贡献保留（H-005 细则待确认）。

### 3.9 选人总流程（v1.2 修正：平台收集志愿，线下协调，回填沉淀）

```
[学习营] 资格名单导入确认 → 名单内导生定向可见并自行报名 → 建组+布置名片
        → 学员申请入池（application 窗口）→ 志愿窗口内市集页提交 3 志愿（单轮，仅选导生，组别继承）
        → 老师导出志愿 CSV → 线下与导生协调/调剂 → 批量指派回填（主路径）
          （导生也可在勾选页自助确认线下已定学员，共用 roster API）
        → 服务端单归属校验 + CampLearningMatch 沉淀 → formation 锁定 → running：课程/考勤/请假/奖励 → closed 档案
[项目营] 老师线下指定负责人 → 平台申报（版本化）→ 管理员审核（负责人关系生效）→ 项目广场
        → 参与者入池 → 项目志愿（单轮，同构，学员可填 3 个项目意向）
        → 导出/线下协调 → 负责人勾选或老师批量回填（3 上限校验）→ 锁定 → 节点/材料/成果 → 档案
```

- **CampMentorPreference 继续使用**：`round` 恒为 1（UQ 兼容现状）；志愿窗口用 `ms_preference_start/deadline` 控制。
- **删除**：round1/round2 两轮机制、`/pick` 在线收人、自动匹配/结算逻辑；`CampMentorMatch` 演进为 CampLearningMatch（provenance 保留）。
- **新增**：`GET /camp/ms/<sid>/export`（志愿宽表 CSV：学员/志愿 1-3/留言/当前归属）+ `POST /camp/ms/<sid>/assign/batch`（幂等批量回填，逐项成败）。
- **市集页保留**为单轮志愿收集入口（名片墙 + 志愿托盘；阶段条简化 collecting→done），沿用刚合并的视觉优化成果；项目营「项目广场」复用名片墙/筛选组件。

### 3.10 里程碑与成果（项目营第一期，阶段 4）

`CampMilestone`（中期/结题：模板说明+截止）、`CampSubmissionVersion`（提交版本化，退回重提新版本）、`CampOutcome`（成果+贡献者+核验状态；**未核验不入个人档案**）。负责人可提交不可自审；审核绑定期望版本。

### 3.11 CampArchive（结营档案，阶段 4；阶段 1 只补写保护）

`POST /archive` 幂等结营：冻结成员与角色、学习归属、项目与角色、出勤请假汇总、课程完成摘要、奖励、成果版本；生成 `CampArchive`。此后所有普通写统一拒绝（**现状 `_camp_writable` 有遗漏，阶段 1 修复**），修正走 `POST /archive/revisions`（专门权限+原因+期望版本→新版本递增，`CampArchiveRevision`）。旧 archived 营期迁移生成「迁移时快照」并标记来源。跨年续做项目=新营期内**重新申报**（沿用 ProjectProfile 复制），不自动继承（简化，替代昨天「按归档状态重启」的说法，见 §10 裁决④）。

### 3.12 课程（阶段 5；阶段 1 只做减法）

- 阶段 1：移除 `/userCourse/enroll` + 前端「加入学习」（A14），课程独立实体独立页面维护，学习入口只走营期。
- 阶段 5：`CourseOffering`（范围=全营/导生组/项目）+ `CourseCollaborator`（管理员授导生共建）+ `CourseEnrollment`（加入实例，UQ(offering,user)）；学习进度关联 enrollment——**这就是 Q15 的正式答案**（原方案 B 的落地形态），届时 LearningProgress 按 offering 实例分档；现有 CampCourse 迁营期级 offering。
- 现有 `GroupModel/CourseGroup` 僵尸债务不动。

## 6. 前端要点

- **营期中心**：升级 `/camp` 为统一营期中心（分组：待我处理/我的营期/可报名/即将开始/历史；卡片=周期+类型+状态+截止+本人身份+主操作），`/camp-home` 收敛为着陆页。
- **人员确认页**（两营共用组件骨架）：固定高度工具栏+名单区，搜索/筛选/勾选/差异预览（保存前显示新增与移除人数）/逐项冲突定位；覆盖加载/空/无权限/阶段锁定/失败状态。禁止大而全 `if category` 万能页——公共外壳+类型子视图/service。
- **项目营页面**：项目广场/详情公开区/我的项目（`已参与 n/3`）/项目工作区/申报与审核（admin）/节点与成果。
- **保留**：市集页为单轮志愿收集入口（名片墙/志愿托盘沿用视觉优化成果，阶段条简化为 collecting→done）；**退役**：两轮候选池、导生在线收人（pick）、自动结算、表格导入入口。
- e2e：同步调整（营期中心、资格名单可见性、志愿导出、批量指派与勾选冲突、3 上限、归档只读）；**E2E/mock 通过 ≠ 真库验证**（§7.3）。

## 7. 迁移与验证

### 7.1 migrate_10_identity（Phase 1a，不变）

等价性校验 → role 刷新（teacher→super_admin；mentor/student→user）→ admin_tag → **DROP user_mode** → rollback 脚本。代码侧：camp_role 重写、48 处门禁清账、payload 删键、role 端点。可独立部署，不需要强制结营，前端不同发。

### 7.2 migrate_11+（营期 schema，按同事 §14.5 分批）

批次顺序：①CampCycle+category/cycle_id/状态字段+CampPolicy（含旧 camp_type 拆分映射与待人工清单）→ ②资格名单表+camp_member 语义升级（role 映射、存量 mentor 回填历史资格）→ ③CampUnit/项目实体/单元成员/事件/学习归属表（camp_mentor_match→CampLearningMatch 适配）→ ④（阶段 4）里程碑/成果/档案 → ⑤（阶段 5）课程三表+UserCourse/LearningProgress 增量迁移。每批 dry-run/执行报告/校验 SQL/回滚边界；不删旧列；双读核对后切流。

### 7.3 验证分层（同事 §18 全文采纳）

后端规则测试（权限/阶段/唯一/上限/错误码）→ **真实 MySQL 事务测试**（并发勾选同一学员、并发抢最后名额、批量部分成功、幂等键）→ 迁移测试（空库/存量/重复执行/回滚）→ 前端组件与营期中心/确认页 → 预览 API 契约同步（5002 fixtures 增加 roster/3 上限数据）→ Playwright e2e → 人工角色检查。**未经真库验证不得标记可交付。**
