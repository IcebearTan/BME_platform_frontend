# BME 视觉与交互规范

适用：用户端、管理端、共享 DewUI。维护日期：2026-11-01。保留现有液态玻璃语言，补齐新增页面及改造区域的统一要求；不宣称历史页面已全部符合。

## 1. 先选择正确的组件与表面

| 场景 | 首选 | 要求 |
| --- | --- | --- |
| 卡片入口、轻操作、导航 | DewCard / DewButton / DewButtonBar | 复用现有玻璃与弹性，不在页面另写折射层 |
| 长文阅读、说明、持续编辑的长表单 | `DewCard variant="flat"` 或已有实心表面 | 高对比、低噪音、内容区不悬浮晃动 |
| 密集数据列表 | DewCard no-hover + Element Plus table | 表格行/单元格使用实心内容底，保留排序/选择等结构能力 |
| 输入、选择、开关 | 已有 DewInput / DewSelect / DewSwitch 等 | 先查组件 props；日期/树/复杂选择等保留现有 EP 结构组件 |
| 对话框、抽屉、浮层菜单 | DewDialog / DewPopover / DewDropdown 或现有 EP 浮层 | 默认实心、清晰可读；不新增玻璃透字效果 |
| 状态 | DewTag / DewBadge / DewProgress | 语义与文字并存，不只靠颜色传达 |
| 数据与图片加载 | DewSkeleton / DewImage | 占位形状对应内容，失败有兜底，见加载态规范 |
| 操作反馈 | DewMessage 或本端已有反馈方式 | 单图标与文字，避免彩色大底、同一操作重复提示 |

共享组件统一从 `@bme/dew-ui` 导入；组件列表以 `packages/dew-ui/index.js` 为准，参数以源码声明为准。`@/components/ui` 只是旧兼容入口，不用于新增代码。不要为视觉一致而重写 Element Plus 已有的复杂交互能力。

## 2. 变量单源与局部主题

| 内容 | 维护位置 | 使用纪律 |
| --- | --- | --- |
| DewUI 色彩/文字/玻璃/圆角/间距/字号/动效 | `packages/styles/tokens.css` | 页面引用变量，不复制配方；新增主题相关 token 同时定义明暗值 |
| 用户端通用页面衬底 | `packages/styles/backgrounds.css` 的 `.dew-page-background` | 已由 user main.js 引入；不要复制 HomeView 或展示页壁纸造另一套背景 |
| 管理端结构变量 | `apps/admin/src/styles/variables.css` | `--spacing-*`、`--text-*`、`--surface-solid` 等沿用本端实际值 |
| EP 视觉桥接 | user `styles/main.css`；admin `styles/global.css` | 通用组件风格在桥接层维护，不逐页覆盖内部类 |
| 管理页布局节奏 | admin `styles/pages.css` | 页头、筛选、分页、弹窗操作区共用，不在 scoped 重定义 |
| XLAB 局部主题 | user `styles/xlab.css` 的 `--xg-*` | 玫红/紫色仅在既有页面族；边界见架构 §4.6 |
| 积分局部主题 | user `styles/points.css` | 既有暖金语义；不覆盖全站主题 |

两端当前存在不同的结构变量值，例如同名 `--radius-*`、`--text-*` 在 admin 会被覆盖。新页面跟随本端节奏；本轮不统一改值。新增公共组件需要两端实际检查，不能只看 user 的效果。

- 正文 `--dew-font`、代码 `--dew-font-mono`；沿用全局字体桥接，不引入外网字体 CDN。
- 文字层级优先 `--dew-text-heading` / `--dew-text` / `--dew-text-muted`，状态用既有语义色；未知/未开放态用中性并写清原因。
- 新布局优先使用现有 spacing/radius/字号变量，避免为每个页面创造相似 token。尺寸、比例与必要布局值可按需求设置；禁令针对绕过系统的视觉配方，不机械禁止所有 px。
- 不在业务页面散落 HEX/RGB 强调色或浅暗两套硬编码；确需领域颜色，在该领域样式集中定义双态变量并说明作用域。
- 禁默认蓝紫渐变装饰。XLAB 的既有粉紫主题、DewUI 内置光效不构成其他页面新增渐变的理由。

## 3. 页面骨架与信息架构

- 用户端沿用全站导航、内容宽度和页面衬底；工作台沿用现有 shell。领域能力进入所属工作区，不重复造顶栏、侧栏或另一个入口。
- 管理列表页沿用架构 §7.1：`.page-header` 标题与筛选/操作区 → `DewCard no-hover` 表格 → `.pagination-wrapper`；复用 `.form-inline`、`.dialog-footer`、`.selectable`。
- 页面只突出当前主要任务；帮助说明放在就近提示/帮助入口，不把技术实现与冗长教程放进业务主流程。
- URL 保存可分享、可返回的关键位置（sid、tab、unit、binding 等按领域契约）；筛选变化按分页约定复位页码，关闭详情与返回保留合理的列表位置。
- 复用现有业务组件处理“查看他人/其他实体”等同构能力，先参数化/扩展，避免复制整页。跨 app 业务实现仍各自持有。

## 4. 交互与状态必须成套

| 状态 | 页面应如何呈现 |
| --- | --- |
| 首次加载 | 与内容相近的 DewSkeleton，避免整页文字跳动 |
| 刷新 | 有数据时保留内容，局部反馈；跨业务范围不展示旧范围数据 |
| 真空态 | 说明当前无记录；有权限时提供下一步，无权限时不提供无效按钮 |
| 失败 | 明确失败原因与重试/返回；不能显示“暂无数据”冒充成功 |
| 未开放/无权限/归档 | 分别说明状态；后端能力控制操作，不能用角色猜测解锁 |
| 提交中/成功/失败 | loading 与防连击；成功同步内容；失败保留表单草稿 |

表单使用可见 label、必填规则与就近错误提示，placeholder 不替代 label。`el-form` 的 rules、ref、字段名都须实际定义；自定义输入配合既有校验流程，不让原生验证与 EP 错误冲突。弹窗重开与切换编辑对象按场景重置数据。

删除、封禁、转交等操作在确认中写明对象和影响；取消属于正常退出。说明性提示保持简洁，重要结果在页面中可再次查看，不只依赖瞬时 Toast。

hover 优先轻位移/形态/底色，不任意切换标题色相。禁用态不可触发操作；焦点、选中与禁用应可区分。新增动画遵守 `prefers-reduced-motion`；不为静态数据表/阅读区加无意义浮动。

## 5. 明暗主题、响应式与可访问性

- 全局主题来自 store，body 与 app 根同步 `.theme-dark` / `.theme-light`；不要增加跟全站脱节的主题开关或仅用 `prefers-color-scheme` 判主题。
- Teleport 到 body 的弹窗、下拉和抽屉也必须继承正确变量；测试页面背景、文字、表格、占位、聚焦/选中、遮罩与错误态两种主题。
- 验收至少覆盖约 1440px 桌面、768px 平板、390–400px 手机。沿用领域现有断点，数值是验收视口，不是要求全站改成统一断点。
- 窄屏筛选与按钮可换行，弹窗不超屏，工作台内容列允许收缩（必要时 `min-width: 0`）。大表格在容器内横向滚动，不能撑宽整页；返回和提交入口始终可达。
- 用语义 button/link；纯图标按钮有可访问名称，装饰图标不重复朗读，内容图片有有意义的 alt；键盘可进入、操作和退出浮层，关闭后焦点回到合理位置。
- 文字与背景保持清楚的对比，不能只靠红绿区分状态；长标题、空头像、缺图、大数字与中文内容都不能破坏布局。

## 6. 共享变更与设计验收

新增 Dew 组件先在 `apps/user/src/views/UiShowcaseView.vue` 加示例，覆盖实际支持的变体与关键状态，再接业务；导出和组件文档同步。阅读型/实心组件不必强行具备玻璃四层。

修改共享 tokens 或组件要检查展示页及双端真实使用处，保存明暗对照；展示页高饱和壁纸只用于检验折射，不是内容页背景标准。页面改动按 [QUALITY.md](QUALITY.md) 验收，有截图才报告截图，有浏览器检查才报告已目检。
