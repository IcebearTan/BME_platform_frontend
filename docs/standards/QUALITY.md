# 前端质量与验收要求

适用：所有前端任务。维护日期：2026-11-01。下面区分必要验证范围与提交门槛，不以历史“本轮只测某专项”限制新任务。

## 1. 按变更范围验证

| 变更 | 至少验证 |
| --- | --- |
| 纯规范、README、注释 | 链接/路径/命令与实际代码一致，`git diff --check`；无需为文档新增 E2E 或启动双端 |
| 单端业务或路由 | `pnpm check:no-emoji`、对应 app 构建、受影响行为的定向用例；页面变更做浏览器验收 |
| 共享 DewUI / tokens | 双端构建、展示页与两端代表使用处明暗/窄屏检查，相关回归 |
| HTTP / 会话 / 共享基础设施 | 双端构建、鉴权与相关业务回归；会话变更覆盖 cookie/compat 和终态/续期 |
| 提交代码前 | 默认 `pnpm check:no-emoji`、`pnpm build`、`pnpm test:e2e`；用户明确限定范围时执行其要求并披露未覆盖项 |

构建通过只证明打包成功；mock E2E 通过只证明指定模拟契约下的行为；真实联调、视觉验收与生产验证分别报告，不互相替代。旧规范所述的用例数量不作为覆盖率指标。

## 2. 命令与环境

从前端仓库根目录执行，Node / pnpm 版本以项目配置与安装工具实际要求为准（packageManager 当前为 `pnpm@11.22.0`）。

```bash
pnpm check:no-emoji
pnpm build:user
pnpm build:admin
pnpm build
pnpm test:e2e

# 用默认配置选择受影响 spec；会启动配置内声明的 webServer
pnpm exec playwright test -c e2e/playwright.config.ts e2e/auth-foundation.spec.js

# 只列出用例，不运行、不代表通过
pnpm exec playwright test -c e2e/playwright.config.ts --list
```

- 真实开发：user 8081、admin 5173、API 5001；开发 env 不改到演示接口。
- 默认 E2E：user 18081、admin 15173，与人工使用的页面隔离；配置另起/复用 5002 演示 API 检查其契约。`.env.test` 的业务 API 为 5001，页面测试应明确拦截所需请求。
- 使用专项 `e2e/playwright.*.config.*` 前先读配置及对应 spec。有些配置只选择用例，不含 webServer，必须另按其中地址启动隔离前端/API；不能把“运行配置”当成自动启动全部服务。
- 不在根目录裸跑 Vite，不把开发端口写进回归用例，不为让测试绿而改用户正在使用的服务配置。

## 3. 有效的行为检查

- 新页面/行为补与风险相符的用例：成功渲染、关键交互、影响权限/错误/状态切换的分支；小型静态修正可复用现有测试，不写只重复实现的断言。
- 登录态 mock 区分 cookie/compat，参照 `e2e/auth-foundation.spec.js`；compat 的本地存储播种仅是该模式的测试准备，不能搬进产品代码。
- mock 返回真实字段和状态，不使用旧全局 teacher/mentor/student 角色掩盖授权问题；营内职责字段可使用其真实职责值。
- 目标接口必须精确断言必要的方法、参数和 body，覆盖与变更相关的失败响应；不能靠所有请求统一 200 空对象证明流程正确。
- 交互检查收集并断言 `pageerror`，防止模板未定义方法/绑定在点击后才报错；断言实际业务效果，不只检查“按钮存在”。
- 优先 `getByRole` / label / 可访问名称定位，避免测试绑定外观类。请求竞态用延迟响应或切换场景验证，不用长时间固定等待掩盖问题。
- 普通 HTTP 来源的浏览器能力限制须按相关专项验证；localhost 通过不能代替项目去重标识的 HTTP 回归。

## 4. 视觉验收矩阵

界面改动至少检查实际受影响的以下维度；不适用项说明原因，避免机械制造全部组合。

| 维度 | 检查点 |
| --- | --- |
| 主题 | light / dark；含 Teleport 浮层、文字对比与焦点 |
| 屏幕 | 桌面约 1440px、平板约 768px、手机 390–400px；无整页横向溢出 |
| 数据状态 | loading / 有数据 / 真空态 / error；缺图与长内容 |
| 交互状态 | 默认、hover、focus、选中、禁用、提交中、错误恢复 |
| 权限与范围 | 允许/拒绝/只读；切营、切项目、换号和归档中与改动相关的场景 |
| 共享影响 | UiShowcaseView + user/admin 各代表使用处 |

检查视觉须实际打开浏览器，操作主要流程并查看控制台/pageerror；仅阅读 CSS 或截图文件名不能算已验收。截图与临时产物放 `screenshots/` 或测试配置指定的结果目录，不散落仓库根。

## 5. 当前自动化边界与完成标准

现有 scripts 包含构建、Playwright、生产源码 emoji 检查和用户端构建后的工作台入口检查。当前未提供统一 ESLint / Prettier / TypeScript 类型检查脚本，也没有全站色值、主题或可访问性的自动门禁；本规范不把人工要求描述成已自动执行的检查。

交付至少说明：修改范围与用户可见结果、实际执行的命令与结果、浏览器验证范围、未执行项/阻碍及其影响。文档变化说明收口的冲突和新增权威入口。只有用例列出、测试未运行、接口被 mock 或后端未启动时，如实注明。

发现历史债务，只在与本次修改相关的范围修正，其他问题记入工作区记录；不要为完成局部任务擅自全站换设计、框架、依赖或数据模型。运行检查后保留可审阅差异，未经授权不提交/推送/发布。
