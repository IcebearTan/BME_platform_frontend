# 前端接口与数据流契约

适用：用户端、管理端及共享 HTTP 基础设施。2026-11-01 从现有架构、客户端和领域服务提炼；下述为新增/修改代码的要求，旧服务尚有返回值不一致的债务。

## 1. 分层与复用

| 层 | 位置 | 职责 |
| --- | --- | --- |
| HTTP / 会话基础设施 | `packages/api/index.js`、`session.js` | baseURL、鉴权注入、401 与续期、会话状态 |
| 本端客户端装配 | `apps/<端>/src/api.js` | 环境配置与 clientType；不堆业务端点 |
| 领域服务 | 本端 `src/services/` 或 `src/domains/<域>/service.js` | URL、参数、响应边界、领域错误适配 |
| 状态/组合函数 | 本端 store、composables 或领域上下文 | 缓存、请求生命周期、跨组件状态 |
| 视图 | views / components / domains 内页面 | 展示与用户意图，不另建 HTTP 客户端 |

新接口优先进入已有领域服务，不给同一端点再建一套平行封装。旧页面直接调用本端 api 可渐进收口，不为整理规范批量重写。两个 app 各自保留业务服务，不跨 app import；只有无业务语义的基础能力适合共享包。

## 2. 先确认真实契约

实现或调整端点前核对服务、后端路由/序列化/授权及相关测试，至少明确：

- 方法、URL、query/body、字段大小写和必填/可空；`0`、`false`、空字符串与缺失值不混用。
- 成功响应、业务失败、HTTP 失败；列表与分页的字段、页码起点、排序和筛选。
- 操作范围与身份：sid、unit_id、projectId、binding、view 等仅按端点需要传递，不猜默认业务归属。
- 权限/能力字段、版本冲突、重复请求语义、上传限制与下载鉴权。
- 时间字段的时区及“日期”还是“时刻”；缺失值的展示与允许的兜底。

没有接口时说明能力缺口，不捏造端点、成功数据或可操作按钮。演示数据放预览/测试环境，不混进生产服务。

## 3. 响应边界与错误

当前 `createApiClient` 返回原始 Axios response，**不会自动解包，也不会统一判断业务 code**。现有 camp/project 服务常返回 `response.data`，points 服务仍返回 Axios response；修改调用链先确认其约定，禁止全局拦截器偷偷改变结构。

- 新增服务默认返回业务响应体 `response.data`，函数说明中写清结构；已有服务保持调用兼容，若改边界须同步所有调用者与相关测试。
- 仅在端点明确使用 `{ code, ... }` 时按其成功码判断，不假设全站都使用 `code === 200`。HTTP 200 不必然代表业务成功。
- 成功的空数组/零记录才是空态；网络失败、无权限、结构缺字段分别呈现对应状态，不用 `.catch(() => [])` 冒充成功。
- 错误文案支持 `error.response.data.message` 为字符串或字段错误对象；字段错误优先贴近表单，另给友好兜底。不要把对象直接传给 Toast，也不直接显示原始堆栈。
- 401 统一交由客户端/会话门面；403 显示无权及可用返回入口；版本冲突保留草稿并提示刷新/重新确认。取消弹窗与主动取消请求不显示“操作失败”。
- 一次失败由一个负责层向用户提示，避免服务层和页面重复弹窗。页面失败应有恢复入口。

## 4. 会话与权限

- 从本端 `api.js` 使用 `authSession`。需要会话的路由先 bootstrap 再判断；业务代码不读取或写入 token 存储，不自行拼 Bearer。
- cookie 模式 access token 在内存，compat 模式的持久化由门面管理；store 只是消费同步状态，不能另当会话真相源。
- 续期、终态 machine 与最多一次重放由共享客户端处理，页面不再写无限重试或重复登录跳转。
- 全局 `role` 仅 `super_admin` / `user`。`teacher`、`mentor`、`student` 等可作为营内职责/视角值，不能拿来比较全局 role。
- 依据服务端 `my_roles`、`available_perspectives`、能力字段和有效关联控制入口；切换界面视角不增加授权，服务端始终重新校验。
- 账号相关缓存和持久化值按端、账号及业务范围隔离；退出、换号与权限终止清理旧数据。

## 5. 请求生命周期与写操作

- 独立请求可以并行，部分失败要各自可见；有上下文依赖的请求顺序执行。
- 搜索、切营、切项目、分页、关闭详情或组件卸载后，取消旧请求或用序号/上下文校验忽略过期响应；过期错误和 finally 也不能改写新页面状态。
- 首次加载给骨架；后台刷新优先保留已展示内容并标注刷新状态。业务范围切换时先清理不属于新范围的数据、选择与弹窗。
- 提交前校验；提交期间 loading 并防重复触发；成功后更新相关视图，失败保留输入，finally 释放状态。危险操作说明对象、影响和确认动作。
- 仅在后端已有契约时携带 `expected_version` / `idempotency_key`。去重键使用 `@bme/api` 的 `createRequestKey`，同一次操作重试沿用同键，新操作生成新键；不改写后端字段语义。
- 不默认重试非幂等写请求。请求去重标识不能当认证凭据；普通 HTTP 页面不直接依赖 `crypto.randomUUID()`。

## 6. 媒体、上传、下载与日期

- 后端相对媒体路径走已有 `assetUrl`：user 在 `services/campService.js`，admin 从 `api.js` 导出。该工具当前直接拼接 baseURL；若字段可返回绝对 URL，先确认/补充领域适配，避免重复拼接。
- FormData 走共享 api，客户端会移除默认 JSON Content-Type，由浏览器生成 multipart boundary；不要手写 boundary。
- 文件类型、数量和体积按端点验证，服务端再次校验。项目营材料的 20 个/48MiB 等限制是领域规则，不推广成全站所有上传的限制。
- 受保护附件先通过鉴权端点获取短签 URL 再打开，不把 token 塞进持久化链接；导出按需要用 `responseType: 'blob'` 并处理错误响应。
- 日期值保留日期语义；本地今天不使用 `toISOString().slice(0, 10)` 代替。项目 D 日数等按项目时区和既有格式函数计算，不能用浏览器时区重算业务结论。

## 7. 交付时留下的证据

接口变化说明请求与响应边界、空态/错误、权限及兼容影响。相关用例至少验证成功、关键失败、范围切换或重复提交中与变更直接相关的行为；mock 必须符合真实字段，不用统一 200 掩盖缺失契约。验证命令和环境见 [QUALITY.md](QUALITY.md)。
